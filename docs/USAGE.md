# 使用说明

## 快捷键

所有十项操作均可在托盘菜单 → 快捷键设置中单独录制、启用或停用。

| 功能 | 新安装默认快捷键 |
| --- | --- |
| 收起当前窗口 | Ctrl+Shift+CapsLock |
| 恢复最近窗口 | Ctrl+Alt+CapsLock |
| 打开管理界面 | Win+F9 |
| 窗口居中 | Win+F12 |
| 窗口上 / 中 / 下循环 | Win+F11 |
| 窗口左 / 中 / 右循环 | Win+F10 |
| 恢复全部窗口 | 默认停用，可自行设置 |
| 打开快捷键设置 | 默认停用，可自行设置 |
| 修复托盘图标 | 默认停用，可自行设置 |
| 退出并恢复窗口 | 默认停用，可自行设置 |

点击“录制”再按组合键，支持 Tab、CapsLock、Win 和普通按键，不再使用 Windows 标准 Hotkey 输入框。Esc 取消，15 秒超时或离开设置窗口会自动取消。录制期间暂时停止本程序已有的键盘钩子；结束后等待松开按键再恢复。单纯浏览设置不会更改配置，必须保存才生效。“恢复默认”也需要再保存。

旧版 INI 中已经保存的键位会保留，新增项补上默认值；想采用上表全部新默认值，请在设置中点击“恢复默认（未保存）”后保存。

更新设置时先检查重复组合并取得新注册，再写配置、提交变更。注册冲突或写入失败会保留旧注册和旧配置。可交换两个功能的键位。启动时单项注册失败只停用该项，在管理窗口和日志中提示，不改写原配置。

### 冲突复核

本程序内部六个默认组合互不重复。没有在微软公开的常规 Windows 快捷键表中找到上述组合的直接常规用途，但系统列表不是所有软件快捷键的全集。

- Ctrl+Shift+CapsLock / Ctrl+Alt+CapsLock 避开了浏览器常用的 Ctrl+Shift+Tab。已通过实际键盘输入验证收起和恢复，CapsLock 状态保持不变。
- 讲述人等辅助功能可能把 CapsLock 作为修饰键；第三方改键工具也可能占用。
- Win+F9 / F10 / F11 仍需以本机注册结果和实际使用为准。
- F12 被 Windows 的 RegisterHotKey 接口列为调试器保留键，因此 Win+F12 使用 AHK 键盘钩子保留原有行为。CapsLock 同样使用钩子，以抑制大小写切换。
- 钩子无法完整检测其他软件钩子的冲突；普通组合通过 RegisterHotKey 获得系统注册冲突反馈。应用内部快捷键也不一定会向系统注册，不能保证自动检测。

参考：[Windows 快捷键](https://support.microsoft.com/en-gb/accessibility/windows/keyboard-shortcuts-in-windows)、[讲述人键盘命令](https://support.microsoft.com/en-gb/accessibility/windows/narrator/appendix-b-narrator-keyboard-commands-and-touch-gestures)、[RegisterHotKey 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey)。

## 窗口和托盘

收起的是当前窗口，不是整个程序的所有窗口。目标进程继续运行；普通窗口隐藏后不会出现在 Alt+Tab 和任务栏窗口按钮中。程序自行创建或重新显示的其他窗口需要分别处理。桌面、任务栏、本程序自身及子控件不作为收起目标。

管理界面列出已收起窗口，可双击恢复。恢复最近窗口会激活它；恢复全部和正常退出恢复只显示窗口，不主动抢焦点。最大化状态会保留。已关闭或自行重新显示的窗口会自动清理；没有列表变化时不重建列表，保留选择。

托盘图标缺失时会重建。启动与任务栏重建后每 2 秒重试，成功即停止重试，最多 15 次；常驻每 30 秒检查一次。已有图标时不删除重建。Windows 仍可把图标放入折叠区，程序不会强改系统显示偏好。

图标不可见时，仍可按管理快捷键或再次启动同一新版 EXE。再次启动只打开已有实例，不重启它，不丢弃已收起窗口。管理员实例只允许“任务栏重建”和“打开管理界面”这两种特定无参数通知通过 UIPI。

## 配置和恢复记录

程序所在目录应允许当前用户写入。

| 文件 | 用途 |
| --- | --- |
| WindowTool.ini | 自定义快捷键 |
| WindowTool.hidden | 隐藏前写入的窗口恢复记录 |
| WindowTool.log | 启动、错误和托盘恢复日志，超过 512 KiB 轮换 |

恢复记录完整写入、刷新并替换成功后才隐藏窗口。正常退出先恢复全部；未能恢复时会保留实例。强制结束进程无法执行退出回调，之后以同一用户和足够权限在原目录启动时，会尝试从记录恢复。窗口属性令牌用于防止句柄重用后误恢复其他窗口。

读取失败或格式损坏时保留原恢复记录并禁止收起新窗口，避免覆盖尚未处理的记录。不要在仍有隐藏窗口或异常退出后删除、移动 `.hidden` 文件。

## 更新已有安装

### 管理员自启动

从长期安装目录运行编译版，在托盘右键菜单打开“设置…”的常规页，勾选“当前用户登录时，以管理员身份启动”并点击应用；普通权限运行时会请求 UAC 授权，必须使用当前用户的管理员权限，不能使用另一个账户。源码模式仅查看状态。移动程序后使用“更新为当前路径（立即）”，这是立即执行的操作。

程序创建当前用户专属的 Windows 登录计划任务，仅在该用户的交互桌面运行，以最高权限延迟 10 秒启动。不保存密码，不限制运行时长，使用电池也可运行；不主动唤醒电脑。真实登录时机仍受 Windows 调度和安装磁盘可用性影响，不能保证修复所有托盘异常。

任务记录当前 EXE 的绝对路径和工作目录。更新时保持路径不变；移动程序后从新位置再次启用。关闭选项只删除带本程序标记的专属任务，不终止正在运行的实例。

启用成功后，仅将当前用户启动文件夹中指向同一 EXE、且没有参数的快捷方式改名为 `.lnk.WindowTool-disabled` 备份。关闭选项不会恢复旧快捷方式；需要恢复原方式时，先关闭计划任务，再把备份改回 `.lnk`。其他路径、带参数的快捷方式、注册表或第三方自启项不会自动修改，应检查是否重复启动。

1. 通过旧版托盘正常退出，确认收起的窗口已经恢复。
2. 备份原 EXE，用新版本替换它。
3. 保留安装目录中的 INI、恢复记录及日志。
4. 重新启动；操作管理员窗口时，以管理员身份运行。

不要同时运行两个版本。异常退出后，应先从原目录以同一用户和足够权限恢复隐藏窗口，再移动安装目录或清理记录。

## 验证范围与限制

本地源码及编译版回归覆盖快捷键配置、冲突与失败回滚、录制回调、窗口定位和隐藏恢复、持久记录、强制终止测试进程后的恢复、过期记录清理、托盘重建消息和二次启动通信。

另在独立测试界面实际录入了 Ctrl+Shift+Tab 和 Ctrl+Shift+CapsLock，使用默认 CapsLock 组合收起并恢复测试窗口，两次后 CapsLock 保持关闭。

0.1.1 源码及编译版各通过 52 项回归；独立编译测试验证了交互会话提权运行、自启启用与更新、关闭、快捷方式迁移和备份冲突回滚。维护者已反馈本机真实登录自启正常，这一结果不代表所有 Windows 环境都已覆盖。

安全软件可能阻止创建计划任务；遇到失败时请检查对应的防护提示，按需审核本程序的具体操作，不建议整体信任 PowerShell 或关闭防护。

真实 Explorer 崩溃重启、各种特殊窗口，以及普通权限二次启动唤起管理员实例，尚未完整覆盖实机验证。模拟 TaskbarCreated 不能替代真实任务栏重启测试；长期稳定性需要日常使用观察。

## 0.1.2 设置与恢复行为

设置分为常规、快捷键、状态与诊断、关于四页。确定会应用修改并关闭；应用保存但不关闭；取消或关闭丢弃未应用的选项。恢复默认只重置当前页的待保存选项。打开日志、刷新状态、重新检测快捷键、修复托盘和更新启动路径属于立即执行的工具操作。

快捷键栏保留用户配置，运行状态另行显示。某键临时被占用时，保存其他设置仍保留这个键位；释放占用后，可在状态与诊断页重新检测。诊断页也提供管理员权限、路径、恢复记录状态与最近错误。

自启是系统设置，快捷键和列表选项是本地配置；如果本地配置已保存但自启操作失败，会明确提示部分完成，并重新读取实际自启状态，不会显示成全部成功。

窗口恢复使用异步请求。单个目标 3 秒未响应时保留恢复记录，可继续恢复其他窗口；稍后可再次尝试。正常退出最多先等待 500 毫秒；仍有窗口未恢复则取消退出。异常退出后的恢复仍需从原目录启动。收起时间仅记录本次运行，上次运行遗留记录显示“上次运行”。

0.1.2 已增加真实无响应测试窗口、快捷键冲突后保存与重试、自启路径及触发器失效的回归。0.1.1 的实机登录验证不能替代 0.1.2 的实机验收；多显示器混合 DPI 与各种特殊程序仍需实际使用确认。

## 0.1.3-alpha.1 预发布说明

统一窗口包含“窗口、常规、快捷键、状态与诊断、关于”。托盘双击和 Win+F9 打开窗口页；设置入口打开常规页。切换页保留未保存修改，恢复操作立即生效。窗口关闭和主动退出均检查未保存修改，可保存、放弃或取消；系统关机、注销不弹出保存询问。

关于页支持手动检查 GitHub 最新正式版，不检查先行版、不自动下载或安装。版本号采用 `0.1.3-alpha.1`，每次交付试用递增末尾编号；后续候选版可使用 `0.1.3-rc.1`，正式版为 `0.1.3`。普通开发修改不自动增加编号。

已知问题：在 150% 主屏和左侧 100% 副屏的组合下，DPI 不感知的 AudioBox 窗口执行水平定位到左边缘时可能向下漂移。保持尺寸的修复已包含，但该位置漂移尚未修复。请暂时避免对该程序循环贴左边缘。

本预发布版需要实机试用；源码和编译回归不代替真实登录自启验证。
## 0.1.3-alpha.2 定位兼容性修复

alpha.1 中列出的 AudioBox 左边缘漂移已修复。对 DPI 不感知及仅感知系统 DPI 的窗口，定位时将外框留在目标工作区内，避免少量不可见边框越过不同缩放屏幕的交界触发坐标重缩放。只约束被定位的轴，不改变另一轴或窗口尺寸；可见内容与左、上边缘之间可能有数像素间隙。逐显示器 DPI 感知窗口继续按可见边框对齐。

在 150% 主屏和左侧 100% 副屏上验证了三种 DPI 模式的连续水平、垂直循环；AudioBox 实测水平 30 次、垂直 30 次均无漂移及尺寸变化。其他特殊程序、缩放和屏幕排列仍应以实机结果为准。

已知限制：窗口定位仍调用同步 SetWindowPos。目标程序无响应时，定位可能拖住主程序；专用无响应窗口实测等待约 4.5 秒。异步恢复窗口的逻辑与此独立，后续将优先处理定位调用的响应性。
