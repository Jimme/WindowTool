# 版本与发布规则

首个公开版本为 **0.1.0**。此前本地试验版本不作为公开发布历史。

项目自有源码采用 **GPL-2.0-or-later**。许可证文本、源码中的 SPDX 标识以及第三方许可声明应随相应发布保留。

版本采用三段数字，但由维护者根据改动范围决定，不因为一次提交或一次任务结束自动递增。

| 改动 | 默认建议 | 示例 |
| --- | --- | --- |
| 错误修复、小调整、小范围兼容改进 | 补丁版本 | 0.1.0 → 0.1.1 |
| 较完整的新功能、明显的行为或界面变化 | 讨论是否递增次版本 | 0.1.x → 0.2.0 |
| 重大不兼容变更、配置迁移或整体定位变化 | 单独讨论 | 不自动升级 |

**每次准备修改版本号或发布前，先说明建议版本及原因，等待维护者确认。** 普通开发时保持版本号不变，可以在更新记录中先记入未发布内容。

确认版本后：

1. 同步入口中的 Ahk2Exe 元数据、运行时显示和更新记录。
2. 根据修改内容执行测试；生成最终 EXE 后验证编译版。
3. 检查公开文件不含本机设置、恢复记录、日志或个人路径。
4. 检查许可证与第三方分发材料是否齐全。
5. 经授权后提交对应源码，创建 `v<版本>` 标签并制作 GitHub Release；EXE、校验值和说明作为附件。

构建脚本只编译，不自动升级、提交或发布。Git 标签和 Release 应对应已经检查、测试并获得维护者确认的源码提交。


测试交付采用 `0.1.3-alpha.1`、`0.1.3-alpha.2` 等编号，候选版可采用 `0.1.3-rc.1`。每次交付递增并先由维护者确认；正式版去掉先行后缀。Windows 数字文件版本使用四段数字记录测试序号，产品版本、关于及诊断显示完整先行版本。
