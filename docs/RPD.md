# WindowTool 产品需求文档（RPD）

本文以 [v0.1.5](https://github.com/Jimme/WindowTool/releases/tag/v0.1.5) 为基线。用户操作步骤见[使用说明](USAGE.md)，版本改动见[更新记录](../CHANGELOG.md)。

## 产品定位

WindowTool 是一个轻量的 Windows 桌面工具。用户可以用全局快捷键收起当前窗口、快速找回窗口，或在当前显示器上重新定位窗口。窗口收起后，所属程序继续运行，普通窗口从任务栏和 Alt+Tab 中消失。收起和恢复以窗口为单位，同一程序的多个窗口可分别处理。

日常操作优先通过快捷键完成，托盘和管理界面提供可见入口。界面使用紧凑的原生控件，参考 Snipaste 的设置布局。窗口标题和托盘名称统一为 WindowTool，完整版本号放在关于、诊断和 EXE 产品信息中。

## 已实现需求

| 功能 | 行为与验收 |
| --- | --- |
| 收起与恢复 | 收起当前受支持的顶层窗口。先完整写入恢复记录，再隐藏窗口。支持恢复最近、双击或选择恢复、恢复全部。恢复全部时不主动抢焦点。已关闭或自行出现的窗口从列表清理。 |
| 异常退出与恢复记录 | 同一用户从原目录以足够权限重启时，尝试找回遗留窗口。校验窗口身份，防止句柄复用后误恢复。记录损坏时保留原件并停止新收起。目标无响应时保留待恢复项，其他窗口仍可恢复。普通退出时若还有窗口未恢复，取消退出。 |
| 托盘与备用入口 | 托盘提供窗口管理、设置和恢复操作。任务栏重建后尝试恢复图标。图标不可见时，可用管理快捷键或再次运行同一路径的程序唤起已有实例，保留收起列表。 |
| 窗口定位 | 左右循环保持纵向位置，上下循环保持横向位置，居中调整两轴。以当前显示器工作区为准，保持窗口尺寸。混合 DPI 下连续定位不得漂移或放大。目标已无响应时跳过定位，保持主程序可操作。桌面、任务栏、已最小化及最大化窗口不参与定位。 |
| 统一界面 | 五个标签依次为「窗口」「常规」「快捷键」「状态与诊断」「关于」。窗口页增量刷新，保留选中项、滚动位置和手动列宽。恢复按钮按列表和选择状态启用。简短状态放在对应页面，详细故障放在诊断页。 |
| 设置应用与回退 | 切换标签保留待应用修改。应用保存常规和快捷键页的待应用变更，确定在应用成功后关闭，取消放弃尚未应用的修改。恢复当前页默认只修改该页的待应用值。关闭或主动退出时如有待保存修改，提供保存、放弃、取消。系统关机和注销跳过保存询问。若快捷键和列表设置保存成功后，自启设置失败，已保存的设置仍然生效，界面说明部分成功。 |
| 快捷键自定义 | 十项操作可单独录制、启用或停用，支持 Tab、CapsLock 和 Win。Esc、15 秒超时、切换标签或离开窗口会取消录制。应用时检查内部重复。新注册失败或 INI 写入失败时保留原配置和绑定。保存其他设置时保留已有的冲突键位，诊断页提供重新检测。关闭 Win+F11 兼容模式时，系统仍占用组合也允许保存关闭状态，并保留该组合供重试。 |
| 管理员登录启动 | 已编译 EXE 可创建当前用户的交互式登录任务，以最高权限延迟 10 秒启动。普通权限下要求同一账户提权。勾选后应用才修改任务。「立即启用并修复自启」立即生效，适用于从新路径更新任务。「重新检测」读取实际状态，保留待应用选择。源码运行和预览模式只可查看。 |
| 手动检查更新 | 在关于页手动查询 GitHub 最新正式版，检查结束后提供发布页入口。网络失败或限流时给出提示，支持重试。下载和安装由用户发起。关于页也可查看项目许可证。 |

### 运行数据与边界

- 程序目录需可写。`WindowTool.ini` 保存快捷键、Win+F11 兼容模式和列表选项。`WindowTool.hidden` 保存待恢复窗口，`WindowTool.log` 保存启动和故障记录。升级时从托盘正常退出，再在原位置替换 EXE，保留运行数据。
- 恢复最近或选中窗口会尝试激活目标。恢复请求异步执行，单个目标 3 秒未响应时保留记录。普通退出最多等待约 500 毫秒，仍有窗口未恢复时取消退出。
- 启动及任务栏重建后的托盘恢复每 2 秒重试，最多 15 次。平时每 30 秒检查，图标存在时保持现状。图标也可能位于 Windows 托盘折叠区。
- 窗口定位先做 50 毫秒响应检查，异步提交后最多等待约 60 毫秒确认。这两个数值受调度影响。旧式窗口可见边缘可能与工作区左缘或上缘留数像素间隙。
- 自启任务保留 EXE 的绝对路径及工作目录。启用后备份当前用户启动目录里指向该 EXE 且无参数的旧快捷方式。关闭自启只删除本程序的专属任务，不恢复旧快捷方式。使用电池时允许启动，不保存账户密码。

## 0.1.4 快捷键兼容性

### 避开 Win+F11 与 Xbox 模式的冲突

**现象**　使用者在日常操作中经常遇到 Win+F11 冲突。Windows 11 在支持且已启用的设备上也使用这个组合进出 Xbox 模式。Windows 的快捷键注册结果能发现部分占用，按键被其他软件钩子拦截等情况仍可能要靠实机确认。 [微软 Xbox 模式说明](https://support.microsoft.com/en-us/servicing/os/windows/docs/2025/10/windows-gaming-full-screen-experience)

**已发布行为**　「窗口上 / 中 / 下」默认使用 Win+F11。快捷键页始终提供默认关闭的「Win+F11 兼容模式」选项。当任一已启用的操作选用 Win+F11 时，显示「Xbox 设置…」入口，入口内说明可能的冲突和处理方式。

入口说明如何在 Windows 设置的「游戏 → Xbox 模式」关闭功能，并可直达该页。普通电脑关闭「启用 Xbox 模式」，游戏掌机把主页应用选为「无」。Windows 提供打开页面的公开接口，由用户操作开关。微软的设备级禁用策略目前仅列为 Insider Preview 支持。 [Windows 设置页面入口](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-settings) · [微软 Games 策略](https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-games#disablegamingfullscreenexperience)

**验收条件**

- 新配置和恢复默认均使用 Win+F11，兼容模式默认关闭。只要有启用项选用该组合就提供 Xbox 设置入口，入口显示与注册结果无关。
- 用户可取消指引或打开 Xbox 模式设置。打开失败时显示手动路径。阅读指引或打开设置均无需应用 WindowTool 配置。
- 关闭 Xbox 模式后可重新检测。若系统仍占用，勾选兼容模式并应用，再按实键验证。诊断中的钩子绑定状态表示 WindowTool 已配置该组合，实键效果仍取决于其他钩子及运行环境。

0.1.4-alpha.1 提供 Xbox 设置入口。

源码和本地编译版各通过 137 项回归检查，覆盖恢复默认、停用、其他操作使用 Win+F11 及切换标签时的入口显示。维护者实测开启 Xbox 模式后 Win+F11 可呼出 Xbox 全屏，关闭后 WindowTool 仍无法使用。安装日志记录 Win+F11 注册失败，Windows 错误 1409（快捷键已被注册）。关闭指引可用于停止呼出 Xbox，释放键位仍需另行验证。

临时 AutoHotkey 钩子实测收到 Win+F11，同时系统注册仍返回 1409。0.1.4-alpha.2 增加默认关闭的「Win+F11 兼容模式」，仅对该组合生效。启用后可能优先处理该键，影响 Xbox 模式及其他使用此组合的软件。点击应用保存，重启后沿用。关闭兼容模式后尝试恢复系统注册，若仍被占用，保留键位并在诊断显示冲突。其他快捷键按原方式处理。

Alpha 2 的源码和编译版各通过 143 项回归检查。维护者试用反馈开启兼容模式后可以上下定位，安装配置也确认保存了兼容模式。

正式版验收补充

- 诊断区分实际使用键盘钩子、使用系统注册、已开启但未绑定，以及系统注册失败。快捷键页保留 Xbox 设置入口并说明勾选后需应用。
- 切换兼容模式时若配置写入失败，保留之前的绑定和设置。正常退出后重新启动应加载已保存的模式。
- 验证录制时暂停钩子、松键后恢复，以及重新检测、取消和恢复默认的行为。
- 正式 EXE 在独立测试目录通过回归后再替换本地安装，保留原有配置和恢复记录。核对编译产物、源码提交和 GitHub 附件校验值。

正式版源码和编译版各通过 151 项回归。新增检查覆盖配置写入失败时保留旧钩子、启动恢复配置、录制暂停和恢复、重新检测，以及诊断区分生效绑定和开关状态。实键验证来自受影响机器上的 Alpha 2 试用。正式版登录自启、不同 Windows 版本的 Xbox 设置可用性及其他软件钩子同时存在时的优先级按实机结果记录。

本地已从 Alpha 2 更新到 0.1.4，日志确认以管理员身份启动。手动更新检查专项测试通过，覆盖实时 GitHub 请求、版本比较、超时和错误恢复。

## 验证基线与边界

- GitHub 发布记录显示，v0.1.3 的源码和编译版各通过 131 项本地检查，覆盖快捷键、窗口恢复及混合 DPI 定位等场景。AudioBox 水平和垂直各连续定位 30 次，未出现漂移或尺寸变化。
- 当时的发布记录还列有正式版真实登录自启待验证。后续改动如果涉及自启或托盘，应分别记录源码测试、编译版测试、真实登录及实际任务栏重建的结果。模拟通知只计入模拟验证。
- 混合 DPI 下，部分旧式窗口贴左、上边缘时允许留数像素间隙。目标在定位请求提交后才卡住时，已提交请求仍可能稍后执行。特殊窗口和不同屏幕排列按实测记录。

### 设计与视觉基准

以 Snipaste 的紧凑原生桌面界面为参考。优先高信息密度、快捷操作、清楚分组、简洁与易用。常用操作尽量同页完成。保留水平五标签、横向排布、分组框与细分隔线，避免宽侧栏、大标题、卡片、大留白、装饰和动画。沿用 AHK v2 和原生 Win32，允许有限绘制。仅实现浅色，集中管理颜色，高对比度保留系统可读性与操作性。深色、自动主题切换、UI 框架更换和无关重构均延后。

### 主窗口与五页

固定客户区宽 528。窗口、常规、快捷键、状态与诊断、关于的目标高度分别为 304、284、416、292、232。根据正式内容测量微调。切页尽可能保持左上角，窗口外框限制在所在显示器工作区。相同页面高度不随列表数量或普通状态改变。一级为真实 Tab3 加有限绘制，方向键、焦点、选中状态可见。若工作区容纳不了基准尺寸，验证可达性，再确定回退。阶段一保留其余四页的旧版控件和操作，允许保留原客户区尺寸，待分阶段接入目标尺寸。

### 托盘悬停

使用原生 `A_IconTip`，由 Windows 绘制。第一行取运行时产品名与版本，接着显示已收起数以及收起、恢复最近和窗口管理三个当前生效的绑定。未配置为「停用」，配置存在但冲突或注册失败为「不可用」，等待应用的改动不得出现在提示中。可用空间足够时追加简短诊断摘要。遵守 127 UTF-16 代码单元限制，按完整行及完整键位取舍，保留版本、数量和核心操作，无生硬截断。

启动、收起/恢复完成、失效窗口清理、已生效快捷键或异常状态变化以及托盘重建时同步。同一提示内容不重复赋值，不新增轮询。保留托盘菜单、双击、单实例和已经实现的图标恢复机制。不新增自定义悬浮窗或依赖。原生提示外观由 Windows 管理。
